# POE2 제작 시뮬레이터 — UI 프로토타입 v0.1

**목표 저장소:** https://github.com/songchoongseok/poe2-crafting-simulator

POE2 일반 장비 제작을 연구할 수 있도록 만든 **한국어 오프라인 수동 제작 인터페이스의 초기 프로토타입**입니다. 현재는 *검증되지 않은 시연 속성 9종*만 사용합니다. 실제 게임과 동일한 등장 확률이나 모든 재료의 규칙을 구현했다고 주장하지 않습니다.

## 바로 실행

- **Node.js 20 이상** 설치 후 프로젝트 폴더에서 `npm run dev` 실행
- 웹 브라우저에서 `http://127.0.0.1:4173` 열기
- **테스트:** `npm test` (추가 패키지 설치 불필요)
- 인터넷 없이 실행 가능한 정적 HTML/CSS/JS 및 로컬 개발 서버로 구성했습니다. `file://`에서 ES 모듈을 직접 여는 경우 브라우저 보안 정책에 막힐 수 있으므로 로컬 서버를 권장합니다.

## 이번 버전에 실제 구현된 기능

| 기능 | 상태 |
|---|---|
| 시작 아이템 등급(일반/마법/희귀), 아이템 레벨, 베이스 선택 | 시연 데이터 기반 동작 |
| 이미 붙은 접두어·접미어와 분열 상태 입력 | 시연 데이터 기반 동작 |
| 오브 버튼 한 번 클릭으로 즉시 사용 | 동작 |
| 진화/확장/제왕/엑잘티드/카오스/소멸 기본 시연 | 동작, 실제 모든 세부 규칙 미검증 |
| 좌측·우측 소멸의 징조 활성화와 소모 구분 | 시연 규칙 기반 동작 |
| 재료별 누적 사용량, 오류 포함 제작 로그 | 동작 |
| 사용 불가 시 아이템과 재료 수량 보존 | 동작 |
| 사용 후 시작 설정 잠금, 새 제작 초기화 | 동작 |

## 아직 구현하지 않은 항목

- PoB2/PoE2DB의 **실제 데이터와 가중치 연결** (현재 `data/demo.js`의 균등 추첨)
- 상위·완벽한 등급별 최소 속성 레벨 규칙
- 분열의 오브, 에센스, 심연의 뼈, 훼손 속성, 액체, 나머지 징조
- 제작된 속성 수 제한 및 모든 특수 예외
- 자동 반복 시뮬레이션과 목표 옵션별 정확한 성공 확률
- 저장/불러오기, PDF Workflow 내보내기, 최종 UI 정식 디자인

**검증되지 않은 규칙이나 확률을 진짜 게임 수치인 것처럼 표시해서는 안 됩니다.** 게임 공식 패치 버전, 데이터 출처, 가중치의 신뢰도, 검증 상태를 추가한 다음 해당 기능을 열어야 합니다.

## 파일 구성

```
index.html                   # 3열 수동 제작 화면
src/app.js                   # 사용자 상호작용·제작 결과 표시·로그
src/engine.js                # 상태 검증과 시연용 제작 로직
src/style.css                # 반응형 다크 UI
data/demo.js                 # 가중치가 검증되지 않은 데모 데이터
scripts/server.mjs           # 추가 의존성 없는 로컬 정적 서버
tests/engine.test.js         # Node 테스트
.github/workflows/test.yml   # GitHub Actions 테스트
docs/POE2_Crafting_Data_Starter_v2.zip # 데이터 수집·검증 기준 문서
```

## 실제 개발 방향

1. PoB2 베이스·속성 데이터를 파싱하고 원본 ID 및 한국어 명칭을 매핑합니다.
2. 실제 등장 가중치를 확인하여 `미확인/추정/검증`으로 구분하고 재료별 최소 속성 레벨을 반영합니다.
3. 오브/징조/에센스/분열/심연 효과를 서로 다른 검증 규칙으로 구현합니다.
4. 정상/사용 불가/속성 그룹 중복/보호 및 제거/확률 검증 테스트를 통과시키고 기능을 공개합니다.
5. 수동 제작 → 자동 시뮬레이션 → 세로형 Workflow 내보내기 순서로 확장합니다.

**작업 원칙:** 주얼은 현재 범위에서 제외합니다. 초기 아이템은 복수 베이스와 원하는 희귀도·기존 속성으로 시작할 수 있어야 하며, 오브는 클릭 즉시 사용합니다. 오브/징조가 실제로 소모됐을 때만 누적 사용량이 증가합니다. 전 과정을 순서대로 로그로 남깁니다.
